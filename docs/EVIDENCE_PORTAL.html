DevOps Viva Voce Questions & High-Scoring Model Answers

CI (Continuous Integration): Developers merge code regularly; every commit triggers automated compile, unit tests, and linting.
CD (Continuous Delivery): Code is automatically tested and packaged into deployable release artifacts, requiring human approval before production push.
CD (Continuous Deployment): Every code change that passes all pipeline quality gates is automatically pushed into production without human intervention.

Tests prevent defect leakage into production. If any unit, integration, or Selenium test fails, the pipeline immediately halts downstream packaging and deployment stages, captures a failure screenshot, and raises an alert. This guarantees zero-defect releases.

An operation is idempotent if executing it multiple times produces the exact same end state as executing it once, without duplicate modifications or errors. In our project:
  • Run #1: Creates user, creates directories, starts container → changed=6.
  • Run #2: Re-evaluates system state against desired state → changed=0.
This eliminates configuration drift across staging and production servers.

A Docker Image is an immutable, read-only template built from a Dockerfile containing application code, runtime libraries, and environment variables. A Docker Container is a running, stateful process instance of that image, isolated using Linux cgroups and namespaces.

Multi-stage builds decouple the compile-time environment (Maven + JDK 21, > 800 MB) from the production runtime environment (Temurin JRE 21, ~210 MB). This minimizes container footprint, accelerates image transfer across registries, and hardens security by removing compilers and build tools from production.
